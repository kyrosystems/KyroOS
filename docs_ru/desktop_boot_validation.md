# Проверка загрузки и рабочего стола

## Что исправлено

- Устранено освобождение общей `kernel_pml4` сборщиком завершённых потоков. Раньше результат зависел от того, успел ли запуститься userspace до уборки selftest-потока. Защита стоит и в reaper, и в `vmm_destroy_address_space`.
- GDT/TSS/IDT устанавливаются до инициализации менеджеров памяти. Double fault и NMI получили отдельные IST-стеки; double fault выводит адреса в COM1 без обращения к графике и heap.
- ISR/syscall stubs очищают DF и выравнивают стек перед C-вызовами. Убрано принудительное `sti` перед `iretq`; планировщик сохраняет исходный IF. Исправлены error-code stubs для #VC/#SX.
- Контекст x87/SSE/MXCSR сохраняется отдельно для каждого потока. Увеличен kernel stack, удалено дублирующее обновление TSS с жёстко заданным размером 8192.
- PCI BAR probing учитывает тип заголовка и 64-битные BAR, временно отключает декодирование адресов и не перезаписывает PCI status при записи command.
- PMM не выделяет физическую страницу 0, не учитывает огромные reserved/MMIO-окна при выборе размера bitmap и проверяет слишком большие запросы.
- `make -j` больше не собирает ISO параллельно с подготовкой его содержимого. Ошибка компиляции приложения прерывает сборку; изменения заголовков приводят к пересборке зависимых объектов.

## Рабочий стол

Используется и дорабатывается существующий KyroDE, а не сторонний оконный сервер:

- Включён графический сеанс для поставляемых учётных записей в `etc/passwd`.
- `init` запускает `/bin/session`; только дочерний процесс сбрасывает UID/GID. После выхода обычного пользователя остаётся возможность следующего входа под root.
- Поддерживается CRLF в `/etc/passwd`; создаются `/root` и `/home/user` с соответствующими владельцами и правами.
- Терминал запускает пакетные команды через `/bin/sh -c`, опрашивает вывод и завершение без блокировки цикла отрисовки. stdin таких команд подключён к `/dev/null`, чтобы они не забирали события клавиатуры у рабочего стола.
- Захват вывода использует отдельный файл на UID/PID с ограниченным режимом создания. `/tmp` имеет режим 01777; удаление чужих файлов ограничено sticky-bit проверкой.
- `F1` — терминал, `F2` — файлы, `F3` — редактор, `F4` — процессы, `F5` — настройки. `Alt+Tab` переключает окна, `Alt+F4` закрывает, `Ctrl+C` прерывает запущенный shell-командный процесс.
- `Esc` открывает диалог сеанса; повторный `Esc` отменяет, `L` в диалоге завершает сеанс.
- Исправлены временной порог двойного клика, удержание заголовка окна в доступной области, пограничные индексы тем, повторное выделение backbuffer и очистка framebuffer с padded pitch.
- Пока графический процесс владеет экраном, текстовый framebuffer не копируется поверх его изображения. Serial-лог продолжает работать.

Это ещё не универсальный desktop stack уровня X11/Wayland: приложения встроены в KyroDE, нет протокола независимых оконных клиентов, PTY/termios, полноценного интерактивного terminal emulator и стандартной модели process groups. Запуск внешних полноэкранных демо временно передаёт им framebuffer. Браузер не является современным HTML/CSS/JS-движком.

## POSIX-подобный API

- `dup`, `dup2` и spawn разделяют файловую позицию и время жизни ресурса; socket/pipe закрываются по последней ссылке. `dup2` корректно освобождает старую цель.
- Исправлены signed PID в `waitpid`, ожидание только собственных детей, `WNOHANG`, ожидание любого ребёнка и нормальное кодирование exit status. Добавлены `WIFEXITED`/`WEXITSTATUS`.
- `mmap` создаёт нулевые private anonymous mappings с откатом при нехватке физических страниц. Неподдерживаемые shared/file-backed mappings больше не имитируются успешным выделением.
- Реализован `mprotect` для anonymous mmap arena, включая `PROT_NONE`, NX при наличии поддержки и проверку всего диапазона до изменений. `munmap` не позволяет освободить kernel/ELF/heap/framebuffer адреса.
- Ошибки старых libc-обёрток нормализуются в `-1` + `errno`. Исправлены проверки режима открытия и отрицательных результатов I/O.
- Добавлены проверки записываемости выходных буферов, канонического userspace-диапазона и постраничное копирование строк/argv для `execve`.

**Полная POSIX-совместимость не реализована.** В частности, `SYS_EXECVE` пока является spawn, а не заменой текущего процесса; `envp` не поддерживается. Нет `fork`, полноценных сигналов, process groups, `poll/select`, shared/file-backed mmap и полной POSIX libc. Номера старого ABI сохранены. Состояние отражено в `abi/syscalls.def` и `abi/posix_matrix.md`.

## Проверки

Сборка выполняется в Linux/WSL:

```sh
make -j4
```

Проверки на хосте из корня проекта:

```sh
python tests/test_abi.py
python tests/run_qemu_tests.py --timeout 30
python tests/desktop_smoke.py --vga std
python tests/desktop_smoke.py --vga vmware --memory 128M --user user
```

Если QEMU отсутствует в PATH, передайте `--qemu <путь-к-qemu-system-x86_64>`. На Windows также проверяется стандартный путь `C:\Program Files\qemu\qemu-system-x86_64.exe`.

UEFI проверяется через отдельные firmware-образы, без изменения оригинального NVRAM:

```powershell
python tests/desktop_smoke.py `
  --uefi-code "C:\Program Files\qemu\share\edk2-x86_64-code.fd" `
  --uefi-vars "C:\Program Files\qemu\share\edk2-i386-vars.fd"
```

`desktop_smoke.py` загружает ISO, входит в GUI, открывает основные приложения, проверяет изменение изображения, запускает `/bin/posixcheck`, выполняет logout и повторный root login. Скриншоты PPM и serial-логи находятся в `build/test/<вариант>/`. `--trace` включает CPU/interrupt trace.

В boot selftests добавлены регрессии sticky-bit защиты и запрета освобождения kernel PML4 при чужой активной CR3; всего 10 проверок. `/bin/posixcheck` проверяет memory mappings, защиту выходных буферов, errno, общий offset дубликатов, pipe lifetime/EOF, spawn и wait status.

Проверка `-vga vmware` означает эмуляцию VMware SVGA **в QEMU**, а не запуск в VMware Workstation. Сам Workstation в этой среде не проверялся. Если он по-прежнему останавливает vCPU, нужны `vmware.log`, настройки firmware/CPU/RAM и COM1-лог именно этой сборки. Исправленные дефекты реальны, но они не доказывают устранение всех возможных причин указанного сообщения.

Поставляемые аккаунты и текущая трактовка `*` в shadow предназначены для development/live-образа; это не production-система аутентификации.

## Дополнение: реальный VMware Workstation

HDD-загрузочной цепочке, выбранной BIOS вместо ISO. Настройка CD-ROM первым
восстановила live-загрузку исходной VM (ISO 1774, selftests 10/10).
